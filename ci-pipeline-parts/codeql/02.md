## 2. Your CodeQL workflow  
**For your Java/Spring Boot application:**
```yaml
name: CodeQL

on:
  pull_request:
    branches:
      - main

  push:
    branches:
      - main

  schedule:
    - cron: '30 2 * * 1'

permissions:
  contents: read
  security-events: write
  actions: read

jobs:

  codeql:
    name: CodeQL
    runs-on: ubuntu-latest

    steps:

      # -----------------------------------------
      # 1. Checkout
      # -----------------------------------------
      - name: Checkout
        uses: actions/checkout@v4

      # -----------------------------------------
      # 2. Setup Java
      # -----------------------------------------
      - name: Setup Java 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: temurin
          cache: maven

      # -----------------------------------------
      # 3. Initialize CodeQL
      # -----------------------------------------
      - name: Initialize CodeQL
        uses: github/codeql-action/init@v3
        with:
          languages: java
          queries: security-extended

      # -----------------------------------------
      # 4. Build
      # -----------------------------------------
      - name: Build
        run: mvn clean package -DskipTests

      # -----------------------------------------
      # 5. CodeQL analysis
      # -----------------------------------------
      - name: Analyze
        uses: github/codeql-action/analyze@v3
        with:
          category: "/language:java"
```
That's the scanning part.

Notice that we **didn't write:**  
```bash
gh api ...
```
and we didn't write:  
```bash
exit 1
```

Why?  

Because we're going to let **GitHub's code-scanning merge protection** handle the policy.  

## 3. What happens when the PR is created?  
Suppose you create:  
```text
PR #123

feature/payment-api
        ↓
       main
```
Because we have:  
```yaml
Because we have:
```

CodeQL runs against the PR. GitHub supports CodeQL analysis on pull requests and reports the results as a code-scanning check.  

Imagine CodeQL finds:   

```text
SQL Injection          HIGH
XSS                    MEDIUM
Weak cryptography      LOW
```
The PR will show the Code scanning results check.  

GitHub's documentation specifically says that new alerts in the PR can appear as annotations, and the code-scanning check contains the results.  

## 4. Now comes the important part: Ruleset  
```text
GitHub Repository
        ↓
Settings
        ↓
Rules
        ↓
Rulesets
        ↓
New ruleset
        ↓
New branch ruleset
```
GitHub's current documentation uses this path for configuring code-scanning merge protection.  

## 5. Create your ruleset  
Give it a name such as:  
```text
Production Branch Security Protection
```
Set:  
```text
Enforcement status:
Active
```
Target branch:  
```text
main
```
Conceptually:  
```text
Ruleset
│
├── Name
│     └── Production Branch Security Protection
│
├── Enforcement
│     └── Active
│
└── Target branches
      └── main
```

## 6. Enable Code Scanning merge protection  
Inside the ruleset, look under Branch protections.  
Select:  
```text
☑ Require code scanning results
```
GitHub's current ruleset configuration specifically provides this option.  

Then you'll get something like:  

```text
Required tools and alert thresholds  

Tool: CodeQL  
```

## 7. Select CodeQL  
Add:
```text
CodeQL
``` 
Then you'll see security alert threshold options.  
Something conceptually like:  

```text
CodeQL

Alerts:
    None
    Errors
    Errors and Warnings
    All

Security alerts:
    None
    Critical
    High or higher
    Medium or higher
    All
```
## 8. This is the setting you want  
Choose:  
```text
Security alerts:  
    High or higher  
```
This means:  
```text
Critical → ❌ BLOCK   
High     → ❌ BLOCK  
Medium   → ✅ ALLOW  
Low      → ✅ ALLOW  
```
Exactly what you were asking for.
