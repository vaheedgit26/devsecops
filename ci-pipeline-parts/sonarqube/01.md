## For a clean/normal Maven JaCoCo setup, configure JaCoCo so that:  
- **`mvn test` → runs tests + collects coverage data (`jacoco.exec`)**    
- **`mvn verify` → runs tests + generates the JaCoCo reports (`jacoco.xml`, HTML, CSV)**    

The key is to bind `prepare-agent` to the test lifecycle and `report` to `verify`.  

**Recommended `pom.xml`**  
```xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.11</version>

    <executions>

        <!-- Attach JaCoCo agent when tests run -->
        <execution>
            <id>prepare-agent</id>
            <goals>
                <goal>prepare-agent</goal>
            </goals>
        </execution>

        <!-- Generate coverage report during verify -->
        <execution>
            <id>report</id>
            <phase>verify</phase>
            <goals>
                <goal>report</goal>
            </goals>
        </execution>

    </executions>
</plugin>
```
**Now the behavior is**  
`mvn test`

```bash
mvn test
```
Maven reaches:  
```text
compile
   ↓
test-compile
   ↓
test
   ↓
JaCoCo agent collects coverage
```
You should get:  
```text
target/
└── jacoco.exec
```
But the **JaCoCo report is not generated**, because `report` is bound to `verify`.  

So:  
```text
mvn test
    │
    ├── Run tests
    ├── Collect coverage
    └── jacoco.exec
```
`mvn verify`  
```bash
mvn verify
```
Maven goes through:  
```text
compile
   ↓
test-compile
   ↓
test
   ↓
jacoco.exec
   ↓
package
   ↓
verify
   ↓
JaCoCo report
```
You should get:  
```text
target/
├── jacoco.exec
└── site/
    └── jacoco/
        ├── jacoco.xml
        ├── jacoco.csv
        ├── index.html
        └── ...
```
So:  
```text
mvn verify
    │
    ├── Run tests
    ├── Collect coverage
    ├── Generate jacoco.exec
    │
    └── Generate reports
          ├── jacoco.xml
          ├── jacoco.csv
          └── HTML
```
**One important clarification**  

**`mvn verify` will run the tests again** if you run it after separately running **`mvn test`**.  

For example:  
```bash
mvn test
mvn verify
```

means the tests are executed twice.  
If you want:  
```text
mvn test   → tests only + jacoco.exec
mvn verify → tests + coverage report
```

that's exactly what the above configuration provides when each command is run independently.  

But in CI, you normally just run:   
```bash
mvn verify
```
because that single command runs the tests and produces the coverage report.  
**For SonarQube**  

With this configuration, SonarQube should consume:  
```text
target/site/jacoco/jacoco.xml   
```
For example:  
```bash
mvn verify

mvn sonar:sonar \
  -Dsonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml
```
So the overall CI flow becomes:  
```text
                 mvn verify
                     │
                     ▼
                Unit tests
                     │
                     ▼
                 JaCoCo
                     │
                     ▼
               jacoco.exec
                     │
                     ▼
              JaCoCo report
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
     jacoco.xml   HTML        CSV
          │
          ▼
      SonarQube
```
This is the configuration I'd recommend for your GitHub Actions + SonarQube pipeline.
